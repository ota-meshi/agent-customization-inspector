# Accessibility受入contract

[English](accessibility-acceptance.md)

**規範対象**: 完全なlocal browser interfaceに対するQR-004とSC-008の受入

**参照**: [Web Content Accessibility Guidelines (WCAG) 2.2](https://www.w3.org/TR/WCAG22/)のLevel AおよびAA

## 判定rule

Release candidateは、下記matrixのWCAG 2.2 Level A/AA success criterionすべてを、4つのprimary
workflow全体にわたり評価しなければならない（MUST）。各行はちょうど1つの確定applicability stateを持つ。

- **Applicable**: 指定された全`AUTO-*` checkが3つの認証browserすべてで合格しなければならない（MUST）。
  `MANUAL-*` checkも指定する行は、そのcheckを未実行として記録する（下記参照）。
- **Not applicable**: 記載のproduct factを完全なrelease diffとbuild済みpackageに照らして再確認しなければ
  ならない（MUST）。そのfactが成り立たなくなった場合、その行はApplicableとなり、release前に合格evidenceを得る。

SC-008が通過するのは、Applicableな全行の自動checkが合格し、Not-applicableのrationaleがすべて成り立ち、
4つのprimary workflowすべてがkeyboardだけで完了し、結果がApplicable行数に等しい0件でないdenominatorを
記録するときだけである。Level A/AAの55 criterionはすべてinventoryに残る。Not-applicable行がdenominatorから
除外されるのは、そのcriterion固有のrationaleが成り立つ間だけである。現在の確定denominatorは37であり、
applicability stateの変更は必ずこの数値と両言語版を同時に更新しなければならない（MUST）。別枠の
「critical defect」逃れやseverity閾値は存在しない。Applicableな自動checkの失敗1件、支持されないNot-applicable
の主張1件、未完了のkeyboard workflow 1件のいずれでもSC-008はfailする。

**手動実行はこのcriterionの外にある。** `MANUAL-*` checkを閉じたmatrixで実行するには、3つのoperating
systemと3つのscreen readerの組み合わせが要り、このreleaseで利用できるどのrunもそれを生めない。
`MANUAL-*` IDは、それを指定する行に残す。手動checkが立証するものはcriterionの実在する一部であり、
IDを残すことがそれを見えたままにする方法だからである。各IDは未実行の残余として記録し、合格として扱わず、
行の合格に算入しない。後にそれらの環境を得たreleaseは、各行が既に名指すmatrixの下でそれらを実行する。

## 安定check IDと実行場所

各行は必須checkの完全な集合を指定する。各安定IDにcriterion番号を含めるため、別criterionでIDを再利用できない。

| ID形式               | 正確な実行場所と記録rule                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AUTO-{criterion}`   | `tests/e2e/accessibility.spec.ts`に置き、test titleへ完全なIDを含めるdeterministic test。Packed release candidateに対してPlaywright 1.61.1の3 projectすべてで実行し、行のproduct固有受入条件をassertする。補助unit/contract testはevidenceを追加できるが、このtestを置き換えられない。`validation.ja.md`のWCAG result tableへ、ID、3 projectすべての結果、artifact path、pass/failを記録する。 |
| `MANUAL-{criterion}` | Procedureは行のproduct固有受入条件であり、下記matrixに対して定義される。このreleaseでは未実行とし、`validation.md`にIDを未実行として理由とともに記録する。結果は記録しない。                                                                                                                                                                                                                   |
| `REVIEW-{criterion}` | 完全なrelease diff、packed-file manifest、render済みpacked interfaceに対して、行に記載した不在preconditionが引き続き不在か再確認する。`validation.ja.md`のWCAG result tableへ、ID、調査したdiff/manifest/build identifier、reviewer、rationale、evidence、pass/failを記録する。                                                                                                                |

`AUTO-*`と`MANUAL-*`の両方を指定する行は、このreleaseでは自動checkで通過し、手動checkは未実行として
記録する。自動結果は手動checkの代替ではないため、そうした行が立証するのは自動の側だけである。
Tool reportがruleを「inapplicable」としただけではNot-applicable行を立証できない。

## Manual checkのmatrix（このreleaseでは未実行）

`MANUAL-*` checkを実行するmatrixは、未実行の作業の形が忘れられず述べられたままになるようここに残す。
このreleaseでは実行せず、そこからの結果も記録しない。

各`MANUAL-*` IDは、3つのplatform cell（VoiceOver付きmacOS、NVDA付きWindows、Orca付きUbuntu）、
5つのviewport/zoom/spacing profile、3つのUI mode、8つのworkflow/state scenario、3つのinput profileの
Cartesian積 — IDあたり`3 × 5 × 3 × 8 × 3 = 1,080`のkeyed cell、36 ID分 — に対して定義される。
実行には3つのoperating systemと3つのscreen readerがすべて要り、それがこのreleaseで自動層を主張する
理由である（spec.ja.md § Clarifications、Session 2026-09-01）。

## 必須execution record

`validation.md`と`validation.ja.md`は、55行それぞれについて、確定state、必須check IDの完全な集合、
各`AUTO-*`と`REVIEW-*` IDのresultとevidence location、row pass/fail、Not-applicable revalidation noteを
記録しなければならない（MUST）。`MANUAL-*` IDは理由とともに未実行として記録し、resultは記録しない。
また、0件ではないApplicable-row denominator、Applicableな自動checkのfailure 0件、4つのkeyboard workflow
outcomeを記録する。両recordは意味的に同等で、調査対象source valueを含まない。
